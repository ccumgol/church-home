## 이슈 21: 첫 화면 배너 티커형/캐러셀형 선택 기능 구현

### 🔴 증상
홈 화면 상단에 **티커형 배너와 캐러셀 배너가 위아래로 동시에 노출**됨. `content/_index.md` 의 히어로 블록에 `active: false` 를 지정했는데도 그대로 렌더링됨.

### 🔍 원인
현재 사용 중인 HugoBlox 모듈(`kit/modules/blox`)에는 **`active` 키를 읽는 코드가 존재하지 않음.** 섹션 목록을 만드는 `hbx/sections.html` 과 블록을 그리는 `parse_block_v3.html` 어디에도 해당 분기가 없어, 값과 무관하게 모든 섹션이 렌더링됨. (구버전 Wowchemy/HugoBlox v5 에는 있던 기능)

### 💡 해결 조치
- `layouts/_partials/hbx/sections.html` 를 프로젝트에서 오버라이드하여 섹션 노출 필터를 추가:
  - `active: false` 인 섹션 제외 (원래 기대하던 동작 복원)
  - `hero_style` 키가 붙은 섹션은 `params.church.hero_style` 과 값이 일치할 때만 노출
- `config/_default/params.yaml` 에 `church.hero_style` 추가 (`ticker` | `carousel`)
- `layouts/_partials/hooks/body-end/custom.html` 에서 **선택된 배너의 스크립트만** 로드하도록 분기. 티커를 쓰면 캐러셀 JS를, 캐러셀을 쓰면 티커 JS를 아예 내려받지 않음.

## 이슈 22: 캐러셀 배경 전체 폭 & 흰색 글자 문제

### 🔴 증상
1. 슬라이드 배경색이 가운데 콘텐츠 영역에만 깔리고 섹션 좌우 끝까지 채워지지 않음
2. 글자가 티커형 배너처럼 흰색으로 나오지 않고 어두운 색으로 표시됨
3. `_index.md` 에 지정한 슬라이드 배경 이미지가 무시되고 보라/파랑 그라디언트만 표시됨
4. `design.slide_height` 를 지정해도 높이가 적용되지 않음

### 🔍 원인
1. `custom.css` 12번 섹션의 `section.hbb-section > div:not(.home-section-bg)` 규칙이 모든 섹션 직계 자식에 `max-width: 64rem !important` 를 강제 → 캐러셀 컨테이너도 1024px로 잘림
2. `custom.css` 3번 섹션의 `html:not(.dark) body:not(.dark) section:not(.dark)...` 규칙(명시도 0,3,3)이 블록 내부의 `.slider-text-white *`(명시도 0,1,1)를 이김
3. 블록 템플릿이 슬라이드 dict 를 만들 때 `background` 키를 담지 않아, 지정한 이미지가 애초에 전달되지 않음. 대신 하드코딩된 5색 그라디언트 순환 사용 (design.md 안티패턴 "보라/파랑 그라디언트 금지" 위반)
4. `slide_height` / `is_fullscreen` 를 블록 템플릿이 읽지 않음

### 💡 해결 조치
- 12번 섹션 선택자에 `:not(.church-carousel)` 를 추가하여 캐러셀을 폭 제한에서 제외
- 캐러셀 섹션에 `css_class: "dark church-carousel"` 부여. `dark` 가 붙으면 3번 섹션의 `section:not(.dark)` 조건에서 스스로 빠지므로 흰색 글자 규칙이 정상 적용됨
- 블록을 다시 작성하여 `background.media` 를 실제로 읽고, 배경 이미지 위에 어두운 막(scrim)을 덮어 어떤 사진에서도 흰 글씨가 읽히도록 함. 배경 미지정 시에는 design.md 팔레트에 맞는 **테라코타 계열** 기본 배경 사용
- 높이를 `--carousel-height` / `--carousel-height-mobile` CSS 변수 하나로 통일. `design.slide_height`, `slide_height_mobile` 값이 인라인으로 주입됨
- 클래스 이름 주의: 제목에 `title` 을 쓰면 2번 섹션의 `[class*="title"]` 규칙이 글자 크기를 덮어쓰므로 `church-carousel-heading` 사용. 버튼은 `.dark a:not([class*="button"])` 의 호박색 링크 규칙을 피하려고 `church-carousel-button` 사용
- 한글 제목이 어절 중간에서 잘리는 문제를 `word-break: keep-all` 로 해결
- 모바일에서는 좌우 이동 버튼을 숨기고 **스와이프**로 대체 (좁은 화면에서 버튼이 글을 가림)

## 이슈 23: 행사 포스터 필드 정리 및 빌드 중단 오류 해결

### 🔴 증상
- 빌드 시 경고: ``page "/event/...": `image` frontmatter must be an object``
- 행사 문서에 `publish_to_home: true` 를 넣으면 **사이트 빌드 전체가 실패**
  ```
  can't evaluate field filename in type string
  ERROR error building site
  ```

### 🔍 원인
`image` 라는 이름을 두고 두 가지 표기가 충돌하고 있었음.
- Decap CMS 의 `image` 위젯은 **문자열**(`/media/uploads/x.png`)로 저장하고, 행사 목록/상세 레이아웃도 문자열로 사용
- 반면 HugoBlox 코어와 캐러셀 블록은 **오브젝트**(`{filename: ...}`)로 기대하여 `.Params.image.filename` 을 호출

즉 CMS로 만든 행사를 배너에 올리는 순간 문자열에 `.filename` 을 요구하게 되어 빌드가 죽는 구조였음. 더구나 CMS 행사 컬렉션에는 `publish_to_home` 필드 자체가 없어, 관리자가 웹에서 만든 행사는 배너에 올릴 방법이 없었음. 설명 필드도 CMS는 `description`, 캐러셀은 `summary` 로 서로 달랐음.

### 💡 해결 조치
- HugoBlox 예약어인 `image` 를 피해 행사 포스터 전용 필드 **`poster`** 도입 (문자열). 기존 `image` 표기도 계속 읽도록 폴백 유지
- 설명 필드를 `summary` 로 통일 (기존 `description` 폴백 유지)
- 미디어 경로 해석을 `layouts/_partials/church/media_url.html` 파셜 하나로 모음. 절대경로·파일명·`{filename:}` 오브젝트를 모두 받아 처리하므로 표기 차이로 빌드가 깨지지 않음
- Admin 행사 컬렉션에 **홈 화면 배너에 표시**(`publish_to_home`) 체크박스와 **행사 포스터**(`poster`) 필드 추가
- 결과: 경고 2건 → 0건, `publish_to_home` 을 켜도 빌드 정상

1. **루트 `hugo.yaml` 이 통째로 무시되고 있었음.** Hugo 는 루트 설정 파일을 하나만 읽고 `hugo.toml` 을 우선하므로, `hugo.yaml` 에 적어 둔 `defaultContentLanguage: ko`, `languageCode: ko-kr`, 교회 주소/전화번호가 전혀 반영되지 않음. `hugo config` 로 확인 시 실제 값은 `defaultcontentlanguage = 'en'`. 게다가 그 안의 module import 는 더 이상 쓰지 않는 구버전(`blox-bootstrap/v5`)을 가리키고 있었음
2. 한국어 사이트인데 `hasCJKLanguage: false` → 한글 문단이 '한 단어'로 세어져 `.Summary` 와 읽는 시간 계산이 사실상 무의미했음
3. 렌더링 결과 덤프(`index.html` 144KB, `index_live.html` 144KB, `main_dump.html` 0B)와 `hugo_server.log` 가 저장소에 커밋되어 있었음
4. Admin 업로드 경로가 `static/media/uploads` 라서 Hugo 가 손댈 수 없었음 → 교인이 올린 **6.17MB PNG 원본이 그대로 방문자에게 전송**됨

### 💡 해결 조치
- 죽은 루트 `hugo.yaml` 삭제. 교회 연락처는 `params.yaml` 의 `church.contact` 로 옮겨 단일 출처화
- `config/_default/hugo.yaml` 에 `hasCJKLanguage: true` 설정
- 디버그 덤프 3종·`hugo_server.log` 추적 해제 후 `.gitignore` 에 등록
- 사용되지 않던 `assets/js/custom.js`(console.log 한 줄), `layouts/shortcodes/test_ticker.html` 제거
- 레거시 경로 `layouts/partials/` → Hugo 0.146+ 표준인 `layouts/_partials/` 로 이동
- Admin 업로드 경로를 `assets/media/uploads` 로 변경하고, `media_url` 파셜이 가로 1600px 초과 이미지를 자동으로 WebP 축소하도록 구현
  - **6.17MB PNG → 314KB WebP (약 95% 감소)**

## 이슈 25: 배너 종류를 Admin 페이지에서 바꿀 수 있도록 개선

### 🔴 요구사항
티커형/캐러셀형 전환을 개발자가 `params.yaml` 을 편집하지 않고, 교회 담당자가 **Admin(`/admin/`) 화면에서** 직접 바꿀 수 있게 해 달라는 요청.

### 🔍 검토
Decap CMS 는 글 폴더뿐 아니라 **파일 하나를 편집하는 `files` 컬렉션**을 지원하므로 기술적으로 가능. 다만 편집 대상을 `config/_default/params.yaml` 로 잡으면 안 됨 — Decap 은 저장 시 자기 데이터 모델대로 **파일 전체를 다시 쓰기 때문에**, 그 파일에 들어 있는 HugoBlox 전체 설정과 주석이 모두 사라짐.

### 💡 해결 조치
- Admin 전용 설정 파일 `data/settings.yaml` 을 신설. 이 파일만 Decap 이 다시 쓰므로 다른 설정이 손상되지 않음 (대신 이 파일에는 주석을 두지 않음)
- `layouts/_partials/church/settings.html` 파셜로 값 해석을 일원화
  - 찾는 순서: `data/settings.yaml` → `params.church.*` → 코드 기본값
  - `hero_style` 이 `ticker`/`carousel` 이 아니면 **빌드를 깨뜨리지 않고** 경고 후 `ticker` 로 처리
  - 파일이 아예 없어도 정상 동작
- Admin 에 **⚙️ 사이트 설정 → 첫 화면 배너** 화면 추가 (배너 종류 드롭다운 + 캐러셀 전환 간격)
- 전환 간격은 관리자가 이해하기 쉽도록 **초 단위로 입력**받아 템플릿에서 ms 로 변환. 이에 맞춰 `_index.md` 의 `design.interval` 은 제거하여 설정 위치를 한 곳으로 통일
- 부수 수정: `site.Data` 가 Hugo 0.156 에서 deprecated 되어 `hugo.Data` 로 교체 (빌드 경고 제거)

### ✅ 확인
- 티커/캐러셀 양쪽 모두 경고·오류 0건으로 빌드
- 잘못된 값 입력 시 경고 1건 + 티커형으로 안전하게 폴백
- Admin 화면이 설정 오류 없이 로드되고 컬렉션 3개(사이트 설정/주일설교/행사안내) 정상 등록

## 이슈 27: 메뉴바 테두리·하위메뉴 먹통 및 디자인 후속 수정

### 🔴 증상 (가장 시급)
1. 메뉴바의 메뉴마다 **둥근 사각형 테두리**가 생김
2. **하위메뉴(2차 메뉴)가 전혀 열리지 않음**

### 🔍 원인 — 두 증상이 같은 한 줄에서 나왔습니다

이슈 26 재작성 때 넣은 규칙이 잘못된 요소를 잡고 있었습니다.

```css
/* 잘못된 코드 */
header nav .nav-dropdown {   /* ← 이건 <ul>이 아니라 부모 <li> 입니다 */
  border: 1px solid var(--rule);
  border-radius: 0.75rem;
  overflow: hidden;          /* ← 절대배치된 하위메뉴를 잘라냄 */
}
```

`.nav-dropdown` 은 드롭다운 패널이 아니라 **메뉴 항목 `<li>`** 입니다. 여기에
테두리를 주니 메뉴 글자마다 둥근 상자가 생겼고, `overflow: hidden` 이
`position: absolute` 인 하위 목록을 잘라내 화면에서 사라졌습니다.
실제 패널은 `<ul class="nav-dropdown-list">` 입니다.

### 🔍 원인 2 — 모바일에서는 애초에 열 방법이 없었습니다

프레임워크의 토글 스크립트는 다음 요소에만 붙습니다.

```js
document.querySelectorAll(".nav-dropdown > .nav-link[role='button']")
```

그런데 이 프로젝트의 navbar 오버라이드는 모듈 원본의
`<span role="button" tabindex="0" aria-haspopup aria-expanded>` 를
`<a href="...">` 로 바꿔 두어 **`role="button"` 이 없었습니다.** 그래서
스크립트가 아무 요소에도 붙지 않았고, hover 가 없는 터치 기기에서는
하위메뉴를 열 방법이 존재하지 않았습니다.

### 💡 해결 조치
- 드롭다운 스타일 대상을 `.nav-dropdown`(li) → **`.nav-dropdown-list`(ul)** 로 교정.
  `overflow: hidden` 제거
- navbar 오버라이드의 상위 메뉴를 모듈 원본과 같은
  `<span role="button" tabindex="0" aria-haspopup aria-expanded>` 로 복원.
  `config/_default/menus.yaml` 상 상위 메뉴 주소가 항상 첫 번째 하위 항목과
  동일하므로 갈 수 있는 곳은 그대로입니다
- 결과: 트리거 6개 정상 바인딩, PC(hover·click)/모바일(tap) 모두 열림,
  `aria-expanded` 갱신, 키보드 Enter/Space/Escape 지원

### 🎨 함께 반영한 후속 수정
| 요청 | 조치 |
|------|------|
| 'Latest Sermon · 최근 설교' 문구 변경 | **The Word of God · 하나님의 말씀** |
| 설교 정보 순서 | 날짜·본문·설교자 → **본문 · 설교자 · 날짜** |
| '지난 설교 다시보기' 밑줄 제거 | `.prose a` 의 밑줄 규칙과 명시도가 겹쳐, `a.latest-sermon-link` 로 요소 선택자를 함께 지정 |
| 예배 및 모임 시간 모바일 2열 | 모바일 구간에서만 `grid-template-columns: repeat(2, 1fr)` |
| CTA 주소·연락처 흰색 | 카드 안 모든 글자를 흰색으로 |
| CTA 버튼 글씨 검은색 | 흰 버튼 위 글자를 `#1c1917` 로 (버튼 안 span 까지) |

## 이슈 28: 양육 메뉴 앵커 전체 미작동 및 페이지 형식 통일

### 🔴 발견 — '양육' 메뉴 8개가 전부 이동하지 않고 있었습니다

"1차 메뉴를 클릭했을 때 2차 메뉴의 가장 위 문서로 연결해 달라"는 요청을 확인하다가
훨씬 큰 문제를 찾았습니다.

| 위치 | 값 |
|------|-----|
| `menus.yaml` 에 적힌 주소 | `/biblestudy/#TEE` |
| 실제로 만들어진 링크 | `/biblestudy/#tee` |
| 문서 안의 앵커 | `id="TEE"` |

Hugo 의 `relLangURL` 이 주소를 **소문자로 바꾸기 때문에**, 대문자로 적은 앵커와
어긋나 브라우저가 이동할 곳을 찾지 못했습니다. 양육 메뉴의 8개 항목
(열린성경공부·커피브레이크·회복의 삶·회복학교·제자의삶·심리상담북클럽·실버코스·미션퍼스펙티브스)이
모두 페이지 맨 위로만 떨어지고 있었습니다.

교회소개(`#greeting`, `#services` 등)는 원래 소문자라 정상이었습니다.

### 💡 해결
- `content/biblestudy/index.md` 의 앵커 8개와 `menus.yaml` 의 주소 9곳을 소문자로 통일
- 빌드 결과물에서 **상단 메뉴 내부 링크 26개 전부**에 대해
  '대상 페이지 존재 + 앵커 존재' 를 검사하는 스크립트로 확인 → 문제 0건

### 🔧 상위 메뉴 동작 재설계

이슈 27 에서 모바일 대응을 위해 상위 메뉴를 `<span role="button">` 으로 바꿨더니
이번에는 **눌러도 이동하지 않는다**는 문제가 생겼습니다. 둘 다 만족시키기 위해
`static/js/church-nav.js` 를 새로 두고 화면 크기로 동작을 나눴습니다.

| 화면 | 동작 |
|------|------|
| PC (1024px↑) | 링크 그대로 이동 (하위메뉴는 hover 로 열림) |
| 모바일 | `preventDefault` 후 하위메뉴 펼치기 |

프레임워크 기본 스크립트(`role="button"` 대상)는 PC 에서도 이동을 막아 버리므로 쓰지 않습니다.
바깥 클릭·Escape 로 닫기, 아래 방향키로 열기도 함께 넣었습니다.

### 🎨 함께 반영한 수정
| 요청 | 조치 |
|------|------|
| CTA 버튼 글씨색 | 검은색 → **카드 배경과 같은 테라코타** (`--color-primary-700`) |
| 주일설교 3열 | `xl:grid-cols-3` → `lg:grid-cols-3`. 예전에는 1280px 이상에서만 3열이라 사실상 2열이었습니다 |
| 주일설교 폭 | `max-w-7xl` → `.page-shell` (1088px). 다른 페이지와 동일 |
| 커뮤니티 문서 헤더 제각각 | `_default/list.html`·`_default/single.html` 도 공용 `page_head` 파셜을 쓰도록 변경. 커뮤니티 6개 문서가 같은 헤더·같은 폭 |
| 헤더 선택 옵션 확대 | 이제 **메뉴로 들어가는 모든 문서**에 적용 |
| 예전 설교말씀 헤더 | **말씀형(`sermon`)** 으로 세 번째 선택지 추가 (밝은 주황·앰버) |

### ✅ 확인
- 배너/티커 × 배너형/말씀형/편집형 **6가지 조합 모두 경고·오류 0건**
- 메뉴 링크 26개 전부 대상 존재 확인
- PC 클릭 시 이동 / 모바일 탭 시 펼침 — 양쪽 모두 동작 확인
- 주일설교 3열(240px×3), 폭 1088px — 다른 페이지와 일치

## 이슈 29: Admin 게시판 기능 확장

### 🔴 요구사항
1. '문서 제목 모양' 을 '첫 화면 배너' 와 **별개 항목**으로 분리
2. 게시판(주일설교·교회소식·주보·포토앨범·행사안내)을 Admin 에서 입력
3. 포토앨범은 본문 없이 **Google 포토로 바로 나가는 링크**로 (썸네일·제목·날짜 포함)

### 💡 해결 조치

**1. 설정 화면 분리** — Decap 은 화면 하나가 파일 하나를 통째로 다시 씁니다.
한 파일에 두 화면을 물리면 서로의 값을 지우므로 파일부터 나눴습니다.

| 화면 | 파일 |
|------|------|
| 첫 화면 배너 | `data/settings.yaml` |
| 문서 제목 모양 | `data/heading.yaml` |

`church/settings.html` 이 두 파일을 모두 읽고, 예전처럼 `settings.yaml` 에
`page_heading_style` 이 남아 있어도 인식하도록 폴백을 두었습니다.

**2. 게시판 컬렉션 3종 추가** — 교회소식·주보·포토앨범

**3. 목록 렌더링 일원화** — `church/board_list.html` 하나가 세 게시판을 모두 그립니다.
목적지는 글마다 다음 순서로 정해집니다.

```
external_url (포토앨범 → Google 포토, 새 창)
  → file (주보 → PDF, 새 창)
    → 상세 페이지 (교회소식)
      → 아무것도 없으면 <div> 로 (죽은 링크 방지)
```

### 🔧 해결 과정에서 만난 문제 4가지

| 문제 | 원인과 해결 |
|------|-------------|
| `_build` 로 빌드 실패 | Hugo 0.145 에서 `build` 로 이름이 바뀜 → 교체 |
| 앨범·주보 목록 페이지가 통째로 사라짐 | `cascade` 의 `build.render: never` 가 목록 페이지 자신에게도 적용됨 → `target.kind: page` 로 일반 글에만 한정 |
| `cascade._target` 경고 | Hugo 0.156 에서 `cascade.target` 으로 변경됨 → 교체 |
| 카드가 `&lt;a class=...` 로 출력됨 | 껍데기 태그를 `<{{ $tag }}>` 처럼 변수로 만들면 Hugo 가 `<` 를 이스케이프함 → if/else 로 나누고 속 내용은 `board_card_inner.html` 로 분리 |

**Admin 목록에서 `_index.md` 제외** — 처음에 `filter: {field: type, value: album}` 로 걸렀는데,
`type` 은 cascade 로 주므로 **글에는 없고 `_index.md` 에만 있어** 정반대로 동작했습니다.
글에만 붙는 숨은 값 `board` 를 두고 그것으로 거르도록 바꿨습니다.

**PDF 안전 처리** — `media_url` 파셜이 `and (eq .ResourceType "image") (gt .Width ...)` 로
크기를 검사하고 있었는데, PDF 에는 `.Width` 가 없어 오류가 날 수 있는 구조였습니다.
`if` 를 겹쳐 쓰도록 고쳤습니다.

### ✅ 확인
- 배너 2종 × 헤딩 3종 **6개 조합 모두 경고·오류 0건**
- `data/heading.yaml` 이 없어도 배너형으로 정상 동작
- 포토앨범 카드: `<a href="https://photos.google.com/" target="_blank">` + 썸네일 + 날짜 + 제목
- 주보 카드: PDF 없으면 상세 페이지로 폴백 (링크 끊김 없음)
- 렌더 아티팩트(이스케이프된 태그 포함) 0건

## 이슈 30: 강조 색상을 Admin 에서 변경

### 🔴 요구사항
홈페이지 전체의 강조색을 Admin 에서 바꿀 수 있게 할 것.

### 🔍 설계 판단

색의 원본은 `data/themes/church-warm.yaml`(테마팩)입니다. 하지만 **Decap 은 편집
대상 파일을 통째로 다시 쓰기 때문에**, 이 파일을 Admin 에 물리면 강조색만 바꾸려다
`surfaces`(배경·푸터색)까지 날아갑니다.

또 프레임워크의 표준 override 지점인 `params.yaml` 의 `theme.colors` 도 쓸 수 없습니다.
그 파일에는 HugoBlox 전체 설정이 들어 있어 Admin 이 손대면 안 됩니다.

그래서 **강조색만 담는 작은 파일**(`data/theme.yaml`)을 두고, 프레임워크가 출력한
CSS 변수를 `head-end` 훅에서 다시 선언해 덮어쓰는 구조로 잡았습니다.
165줄짜리 `get_theme_config` 파셜을 포크하지 않아도 됩니다.

```
data/theme.yaml
  → church/accent.html                     밝은/어두운/보조색 계산
    → hooks/head-end/custom.html           --color-primary-* 재선언 (테마팩 <style> 뒤)
```

### 💡 구현

- 프리셋 6종(테라코타·앰버·올리브·버건디·네이비·퍼플) + 직접 지정
- 한 색만 고르면 나머지는 자동 계산
  - 어두운 모드: 흰색 쪽으로 18% 밝게
  - 보조색(그라디언트 방향): 22% 어둡게 — 같은 계열이라 어떤 색을 골라도 안전
  - 50~950 스케일: 프레임워크의 `generate_color_scale` 을 그대로 재사용
- 기본값 terracotta 는 테마팩과 **똑같은 값**을 직접 적어 두어, 설정을 건드리지 않은
  상태에서는 화면이 지금과 완전히 동일

### 🔧 결정적으로 필요했던 후속 작업

프리셋을 네이비로 바꿔 확인해 보니 **아이브로만 바뀌고 재생 버튼·본문 배지·태그
사이드바는 그대로 주황**이었습니다. 레이아웃에 `orange-600` 같은 **고정 색 이름이
215곳** 박혀 있었기 때문입니다.

| 파일 | 건수 |
|------|------|
| `shortcodes/church_staff.html` | 122 |
| `sermons/list.html` | 63 |
| `sermons/single.html` | 14 |
| `shortcodes/pastor_greeting.html` | 13 |
| `single.html` | 3 |

`orange-*` → `primary-*`, `amber-*` → `secondary-*` 로 일괄 치환했습니다.
치환 후 Tailwind 가 새 유틸리티를 실제로 만들어 내는지(`bg-primary-950/40` 같은
투명도 조합 포함) 빌드 산출 CSS 에서 확인했습니다. 58종 정상 생성.

### ⚠️ Hugo 문법 함정
파셜에는 `return` 이 **하나만, 맨 끝에** 올 수 있습니다. 조기 반환을 쓰려다
`wrong number of args for return` 오류가 났고, 결과를 변수에 담아 마지막에 한 번만
돌려주도록 고쳤습니다.

### ✅ 확인
- 프리셋 6종 + 직접 지정 + 잘못된 이름 + 파일 없음 — **모두 빌드 성공**
- 잘못된 값은 경고만 남기고 기본색 유지 (사이트 안 깨짐)
- 기본값(terracotta)의 최종 CSS 값이 테마팩과 **밝은/어두운 모두 완전 일치**
- 네이비로 바꿨을 때 CTA 그라디언트·버튼·아이브로·재생버튼·사이드바까지 전부 전환
